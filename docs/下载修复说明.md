# 下载可靠性修复说明

本次改动解决了“下载失败却显示完成”“超时查询覆盖下一首的信息”“同名坏文件被当成已下载”等问题。下载结果现在分别统计成功、失败、已验证文件跳过、手动跳过，并列出失败项。进度中的“已处理”表示队列处理进度，不表示每首都成功。

专辑目录会附加专辑编号；混合歌单保存的封面以专辑编号区分。下载文件会带上歌曲编号和所选/确认的音质，旁边生成 `.qbdlx.json` 校验记录。只有歌曲编号、音质、文件内容校验和实际音频参数都一致才会跳过。已有旧文件没有校验记录时不会被直接信任；在跳过模式下会保留它，保存新的已验证副本。请保留这些校验记录，否则程序需要重新验收/下载。

最高档 FLAC 要达到平台对该曲声明的最高位深和采样率。程序会核对接口返回的歌曲编号与参数，再检查收到的文件。如果不一致，会记录失败，不会悄悄降低档位，也不会通过升频冒充高音质。普通 CD 音源仍是普通 CD 音质，选择最高档不能制造原本不存在的信息。MP3 是有损格式。现在检查连续的全部音频帧并逐帧解码，拒绝中段损坏、截断、CRC 错误和不完整解码，再核对时长、采样率、码率和文件校验记录。检查不会重新编码音频。MP3 未必带逐帧校验码，因此不能声称能识别所有仍然能合法解码的内容变化。

临时文件按任务隔离，并且先完成验收、计算文件校验值并准备检查记录，再一起保存音频与记录。覆盖时先保留旧文件，保存失败时恢复它；同一台电脑上的多个程序会协调最终保存和重复改名。两个文件无法由操作系统一次性原子替换，突然断电或跨电脑写入 NAS 的情况仍需单独验收。网络中断、429 和部分服务器错误有有限次数重试，尊重服务器等待要求；失败重试会从头下载，尚不支持断点续传。查询、下载、FLAC/MP3 检查、文件复制和计算校验值均接入停止信号。正常退出会等待下载停止和文件恢复完成。继续采用顺序队列，不承诺多曲并发速度。

FLAC 使用官方 `flac` 工具进行整首解码/CRC/MD5 验证。正常文件只检查，不重新压缩；启用“修复 MD5”时，只对缺失 MD5 的文件重写，再验证修复结果。工具缺失、退出失败或检查超时都不能算成功。Windows 的完整路径达到 260 字符时，会先异步复制到短临时路径供官方工具检查，再清理临时文件；正常音频不改写，缺失 MD5 的修复结果验证后才替换回来。这种长路径检查会增加文件复制，并占用与音频大小相当的临时空间；修复时还需要在原目录中暂存一份音频。

**Windows 运行要求**：.NET Framework 4.8，及官方 FLAC 工具。GitHub 自动测试通过后生成的 Windows 包已附带用于检查的 `flac.exe`，需要完整解压整个目录。其他来源或自行编译的程序需要让 `flac.exe` 位于程序目录或 PATH；可在终端执行 `flac --version` 检查安装。未安装工具时，FLAC 下载会明确失败，而不是跳过验证。这个仓库自带的接口 DLL 仍用于登录和数据模型；下载和列表查询改用可取消、可重试的请求。

密码和应用密钥保护失败时不再保存明文。旧明文密码/密钥在读取时尝试迁移为受 Windows 用户保护的数据；无法保护则清空保存值。其他 Windows 用户无法解密的密码/密钥会被清空并要求重新登录。新日志屏蔽凭据和下载地址；已存在的旧日志不在本次代码改动中自动删除。

备用语言文本的格式、零条目时的数字补位、部分可缺省的标签字段也已修正。

本轮还修复了：跳过最后一首影响下一张专辑；文件夹名称包含 `.flac` 时 MP3 标签误判；歌手名称和角色缺失导致失败；失败清单写入集合编号；相同封面重复下载；搜索封面阻塞窗口；带查询参数、HTTP 或大写的链接识别错误；更新地址指向原作者仓库。

设置和日志现在固定保存在 `%LOCALAPPDATA%\QobuzDownloaderX`。首次读取时会使用程序目录里的旧 `user.config`，下一次修改设置时迁移保存。设置采用先完整写入再替换，保留上一份良好备份，并协调同时启动的程序只合并各自修改的设置。损坏的设置有备份时恢复；没有备份时明确报告错误。正常用户目录不可写时会选用同一个用户的临时目录作为固定备用位置；临时目录里的设置可能被系统清理。

同一批下载中的相同专辑和尺寸只下载一次封面。搜索结果先显示文字和占位图，再在后台加载图片，最多同时加载四张；换搜索和关闭窗口会停止旧图片请求。

## 本轮继续修复的问题

- 列表分多页返回时，根据实际收到的条目数取下一页，避免服务端少返回一页内容就跳过中间的歌曲。专辑、歌单、收藏、歌手和厂牌均有检查；列表中途变化、编号不符或一直重复同一页时会报错。
- 保存密码、应用编号和密钥时加入明确的加密标记；旧版 Windows 加密设置可以迁移，普通密码即使看起来像编码文本也不会误判。无法解密的内容不会作为密码继续使用。
- 长歌名为重复文件改名和校验记录预留空间，临时校验记录使用独立短名称，避免音频下载完整后却因文件名过长而保存失败。
- 同时启动程序时使用不同日志文件，解决两个窗口争用同一个日志的问题。另外检查了重叠保存时的文件/记录配对；这不等于多个电脑写入 NAS 已完成验收。
- 在批量下载两项之间仍可停止剩余队列；退出程序时也会发送停止信号，避免反复触发关闭。
- 登录完成后在原来的窗口处理线程打开主窗口，并拦截重复登录；另外在其他窗口关闭后也明确回到登录窗口所属的线程执行打开主窗口的动作。缺少订阅信息也能打开窗口。语言文件按程序所在目录查找，避免从不同目录启动时找不到中文等语言文件。

## 验证边界

已通过程序编译、针对性自动检查，并用官方 FLAC 1.5.0 检查真实生成音频：正常文件不重新编码，音频内容损坏会失败，缺失 MD5 会修复并再次验证。当前核心检查增加到 Linux 83 项、Windows 80 项；Windows 桌面检查增加到 41 项。包括使用实际下载程序连续处理 200 首的检查，以及旧的 200 首核心模拟检查。通过情况以当前提交对应的 Actions 记录为准。详细命令见 `tests/CoreChecks/README.md`；GitHub 上还配置了 Windows 编译和组件检查，运行状态以 Actions 记录为准。

当前云主机是 Linux；Windows 窗口打开、旧密码迁移、长中文文件名及日志多开检查由 GitHub 的 Windows 机器执行，以对应提交的 Actions 记录为准。尚未使用真实账号进行长时间下载，也未全面验收 NAS、磁盘满或多个程序同时写同一首歌。因此不能据此承诺实际下载速度、零故障或平台接口今后始终兼容。Windows 验收应覆盖多专辑/歌单、服务端降档、网络中断、长路径、磁盘满、停止和重新启动，并核对每首实际参数及失败清单。
