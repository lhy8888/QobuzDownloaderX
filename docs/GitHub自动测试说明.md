# 在哪里看测试和下载程序

打开仓库的 **Actions（自动操作）** 页面：
https://github.com/lhy8888/QobuzDownloaderX/actions

选择 **Windows build and download checks**，再点击最新一次记录。绿色表示这一组检查通过，红色表示存在失败，黄色表示正在等待或运行。点开失败项目能看到原因。

全部必要的检查通过后，记录页面下方的 **Artifacts（生成文件）** 中提供 `QobuzDownloaderX-Windows-tested`。登录 GitHub 后下载、解压里面的 Windows 压缩包，再完整解压程序目录，运行 `QobuzDownloaderX.exe`。包内包含实际用于检查的官方 FLAC 1.5.0 工具及其许可证；Windows 仍需 .NET Framework 4.8。文件默认保留 14 天，可以重新运行生成。

代码每次上传或提交修改请求都会自动检查；也可以在工作流程页面点击 **Run workflow** 手动运行。首次使用分支时，上传也会触发；手动按钮通常需工作流程存在于默认分支。如果 GitHub 提示这个派生仓库的 Actions 尚未启用，仓库所有者需要点击启用，之后再次上传代码或在默认分支手动运行。

## 自动检查的内容

| 检查组 | 实际做的事 | 要发现的问题 |
| --- | --- | --- |
| Windows 编译 | 分别编译 Debug 和 Release，保存编译记录 | 代码错误、缺少文件或依赖，发布版不能编译 |
| Windows 程序组件 | 使用编译后的程序检查窗口控件、内置图片/图标、依赖加载、登录完成后打开主窗口、重复点击及退出处理 | 编译通过但窗口构造或图片读取失败 |
| 网络异常 | 模拟 408、429、503、404、401、等待超时、中途断流、空响应、截断数据、停止重试 | 卡死、无限重试、半个文件被当成成功、停止无效 |
| 信息隔离 | 延迟返回上一首/上一张专辑的信息、错误歌曲及列表编号、少于预期的列表页、重复/缺失列表页、列表中途变动 | 上一首覆盖下一首、漏歌、串歌 |
| 音质和完整性 | 核对歌曲编号、所选格式、位深、采样率、码率、时长；真实 FLAC 整首解码检查及 MP3 逐帧解码/CRC 检查 | 静默降档、损坏内容、错误品质标注 |
| FLAC 修复 | 正常文件保持字节不变；损坏音频被拒绝；缺失 MD5 才修复并重验，包含长中文路径 | 不必要重新压缩、错误修复、校验被绕过 |
| 200 首模拟下载 | 核心程序模拟连续处理 200 首；另外在 Windows 调用实际专辑→歌曲→保存流程连续处理 200 首，部分故意失败或先限流再恢复，核对来源标记、标题、编号和结果 | 连续处理后串歌、失败计数不准、重试错误 |
| 100 首 Windows 标签写入 | 连续写入中文标题、专辑和封面，逐首解码并检查校验记录 | 标签混淆、封面串到下一首、写标签损坏音频 |
| Windows 文件处理 | 实际移动文件、不覆盖旧文件、重复文件改名、替换校验记录、锁定文件、超过 260 字符的中文路径及长歌名 | 文件覆盖、假跳过、不能写却算成功 |
| 密码与日志 | 实际调用 Windows 用户密码保护、读取真实旧版加密设置及看起来像编码文本的明文密码，模拟保护失败，检查日志中的凭据和签名地址 | 明文保存、凭据泄露 |
| 停止与多开 | 批量下载两项之间点击停止、同时构造两个窗口及日志文件 | 剩余队列不能停止、日志文件争用 |
| 设置保存与恢复 | 固定用户目录、旧设置迁移、合并同时修改、锁定文件、损坏后恢复备份 | 设置丢失、写一半损坏、启动位置变化导致读错设置 |
| 搜索封面 | 故意让图片请求一直等待，验证窗口消息处理仍在运行，停止请求并检查独立图片的寿命 | 图片下载让窗口卡住、切换后旧图写入新结果 |
| 已知依赖漏洞 | 检查应用固定版本的依赖及间接依赖；发现公告或无法取得检查数据均报失败 | 使用已公开存在漏洞的依赖 |
| 语言和缺省信息 | 检查各语言文本、旧语言文件后备文本、缺少作者/流派、无效发行年份 | 空值崩溃、结果信息显示错误 |

Linux 核心检查为 **83 项**；Windows 核心检查为 **80 项**（没有 Linux 专用的 3 项假进程检查），Windows 桌面组件检查为 **41 项**，分别针对两种编译版本运行。200 首和 100 首循环各算一个检查项目，循环内每首都有断言。任何一个断言失败，所属检查组都会失败。真实 FLAC 工具是必需条件，不能因工具缺失而把相关检查静默跳过。

每组会保存文本输出和逐项 XML 结果；Windows 还保存详细编译记录。仓库页面中的测试结果用于判断这次提交，不能代表任意账号或网络条件下都不会出错。

## 仍需实际下载验收

自动检查使用人工生成的短音频和模拟网络响应，没有真实账号凭据，也不访问真实 Qobuz 音乐下载。窗口检查会模拟登录成功并实际打开主窗口，实际下载队列使用模拟接口和人工音频，登录、更新及真实音乐下载不访问 Qobuz。它们能发现代码退步，但不能测出你家网络的下载速度，也不能证明平台仍接受当前登录方式。

Windows 实际验收建议：同名歌曲/同名专辑、跨专辑歌单、CD/24bit-96kHz/24bit-192kHz 音源、连续 500 首、拔网恢复、点击停止后重新开始、NAS 目录、长路径、磁盘剩余空间不足、多个程序写同一下载目录。核对每首的实际参数、失败清单和保存的封面；密码迁移、长文件名和窗口打开已有自动检查；以上真实下载场景尚未全面自动执行。

依赖公告扫描不覆盖仓库自带接口 DLL 的内部代码，也不能发现所有未知漏洞。最终的 `QobuzDownloaderX-Windows-tested` 下载项只有在所有检查组通过后才提供。
